# 科研工作台（Obsidian 插件）

本地优先的科研信息系统（当前版本 `0.4.0`）。Markdown 是事实来源，`records.json` 是可重建的派生索引，NMR JSONL 是操作审计记录。

## 主要功能

- 任务和实验记录创建：新记录写入永久 `record_id`（`TASK-*` / `EXP-*`）。
- 科研数据库：统一索引任务、实验、课题、数据、文献、写作和进展。
- 旧记录兼容：没有 `record_id` 的笔记会使用 `LEGACY-*` 标识，不会强制改写旧文件。
- NMR：扫描 Bruker 原始目录，识别 ¹H/¹³C，执行 preflight 后由用户明确确认归档。
- NMR 归档：拒绝路径越界、缺少 `fid`、目标已存在和危险目录嵌套；记录成功/失败审计；批量失败会显示部分成功结果。
- Research Entity Layer：课题、实验、化合物、数据资产统一使用永久 ID；数据库支持关系完整性检查和旧记录迁移。
- NMR 归档完成后自动登记 NMR 数据资产，并保存可选关系。

## 设置

在 Obsidian 设置 → 科研工作台设置中配置：

- 启动时是否打开工作台（默认关闭）。
- 工作台根目录当前固定为 `00-博士工作台`，避免出现设置已修改但目录未迁移的误导。
- NMR 待处理目录和归档目录。

路径不再需要修改源码。待处理目录和归档目录不能相同，也不能将归档目录放在待处理目录内部。当前版本仅支持同一磁盘分区内归档，跨盘移动会在预检阶段拒绝。路径不存在时页面会显示可诊断提示，不会导致插件崩溃。

## 数据位置

- 任务：`00-博士工作台/应用数据/任务`
- 新建实验：`00-博士工作台/03-实验`
- 数据库索引：`00-博士工作台/应用数据/数据库/records.json`（schema v3）
- NMR 审计：`00-博士工作台/应用数据/审计/nmr-archive.jsonl`
- 原有 `实验记录` 目录只读扫描，不会被覆盖。

## 安全边界

NMR 工作流为：扫描 → 选择 → preflight → 展示精确操作 → 用户确认 → 移动 → 写入审计。不会自动删除、不会静默覆盖目标，也不会在后台自动归档。

## 开发

```powershell
npm test
npm run build
```

本插件当前声明为 Desktop-only，因为 NMR 文件系统集成使用 `fs/promises`、`path` 和 `child_process`。核心 Markdown 和数据库逻辑不依赖网络或专有数据库。
